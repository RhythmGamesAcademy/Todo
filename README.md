# TODO

青と白を基調とした、トドのアイコンのTODOアプリです。

## 開発

Node.js 22.12以降（推奨: Node.js 24）を使用してください。

```sh
npm ci
npm run dev
```

表示されたローカルURLをブラウザで開きます。

```sh
npm test
npm run build
npm run preview
```

## 機能

- TODOの作成・編集・削除と、削除直後の取り消し
- 期限日時（任意）、優先度（選択欄は左から低・中・高）、状態（未着手・進行中・完了）
- 期限なしの新規作成、または期限ありから期限なしに変更する際の確認
- カードから開く詳細モーダルと、「自分」と送信日時を表示する、追記専用のチャット形式メモ
- 期限順／優先度順、状態・今日の期限・期限超過での絞り込み、タイトル・説明・メモ検索
- 青い二本の波形ラインと、背景の透過・ぼかし・縁の反射によるLiquid Glass風の固定ヘッダー。トドのロゴ・TODOタイトル・毎秒更新の日時を表示（高さはPC 66px／スマートフォン58px）
- カードの輪郭と影を強め、これから期限を迎える未完了TODOのうち最も近い1件を赤い左縁と期限文字で強調（並び順には依存しない）
- 完了にしたTODOは「すべてのTODO」は完了済みも含め、末尾にまとめます。未完了・完了の各グループ内で選択中の期限順または優先度順を適用します。
- 優先度は高：赤、中：黄、低：緑（文字ラベルも併記）
- カード／リスト表示を切り替え可能。リスト表示はタイトル・説明・期限・優先度のみを表示し、行から詳細を開く。表示形式はこのブラウザに記憶
- チャット履歴と入力欄を同じ角丸のへこんだ領域に配置。メモは送信時に即時保存し、約0.4秒の「…」の後に本文の領域が滑らかに広がる。送信ボタンから入力欄にフォーカスを戻さず、モバイルのキーボードを再表示しない。連続送信も個別に演出。利用者の指定により、メモの演出は端末の「動きを減らす」設定より優先する
- Googleカレンダーの予定作成画面へのリンク（締切から15分間）
- JSONバックアップの書き出しと3方式の復元
- 完了済み／すべてから選べるTODO・メモの一括削除
- レスポンシブ画面、キーボード操作、フォーカス表示、入力破棄・削除の確認

## 文言の変更

画面文言・アクセシビリティラベル・確認ダイアログ・通知・エラー・日時書式は src/messages.ts に集約しています。件数やタイトルを含む文章も、文章全体を組み立てる関数として同じファイルに置いています。文言を変更する際はこのファイルを編集してください。

HTMLの言語、ページタイトルと説明も、Viteのビルド時にこの辞書から設定します。現時点の言語は日本語のみです。将来の多言語化では、同じ構成の辞書と日時書式を言語ごとに用意できます。

## スクロール

メモ履歴には独立したスクロール領域を設け、上下端ではブラウザ標準のスクロール連鎖でモーダル全体へ操作を渡します。モーダルの内容が画面内に収まる場合、全体側はスクロールしません。モーダル表示中は背景ページのスクロールを固定します。

## 完了の演出

未完了から完了への変更が正常に保存されたときだけ演出を予約し、詳細・編集・確認画面を閉じて「未完了」タブへ切り替えてから再生します。カードの面とトドの胴体を同じSVGの閉じた輪郭として補間し、ヒレと尾を独立して動かします。左右の旋回は横移動・奥行き・縮尺・Y軸の向きで表現し、上下反転は行いません。旋回後はいったん身を縮めて後ろに溜め、体を伸ばして加速します。加速に合わせてヒレの動きと水流も速くなり、「完了」の件数へ到着すると水しぶきと件数の弾みで知らせます。初期読み込み、バックアップ復元、完了の取り消し、保存失敗では再生しません。メモの保存・破棄確認を妨げず、演出前にデータ保存を完了します。

「すべてのTODO」は完了済みも含め、末尾にまとめます。未完了・完了の各グループ内で、選択中の期限順または優先度順を適用します。到着後は残件数に応じて緑（0件）・オレンジ（1件）・青（2件以上）の通知を下から表示します。通知は6秒後に消え、ホバーやフォーカス中は消えません。

到着先にはDOM参照を使い、その時点の完了件数の矩形から座標を計算します。画面の種類ごとの固定座標は使いません。上部の横スクロールメニューが隠れていれば先に表示し、遊泳中のスクロールやリサイズも追跡します。トドの体形はロゴをもとに、遊泳用の胴体・手前と奥のヒレ・尾へ分割しています。輪郭とサイズは共通のアニメーションクロックで進めます。演出のスキップ・Esc・タブのバックグラウンド化では即時終了し、描画が停止した場合も時間制限で件数を確定します。演出の成否で保存内容は変わりません。

## 保存と日時

TODOとメモは、このサイトを開いたブラウザのlocalStorageに保存します。ログイン、利用者間の共有、端末間の自動同期はありません。同じ端末でもブラウザやブラウザプロファイルが違えば別のデータです。サイトデータを削除すると消えるため、必要に応じてバックアップを利用してください。URLのドメイン・プロトコル・ポートが変わると保存領域も変わります。

保存失敗時は成功表示をせず、入力を残してエラーを表示します。読み込めない保存データは自動で上書きせず、元データの書き出しと復元・初期化を案内します。

期限は利用者の端末のタイムゾーンで入力・表示し、保存時はISO 8601形式にします。期限順では期限なしを末尾に置き、同じ期限なら優先度順にします。優先度順では同じ優先度内を期限順にします。今日の期限には未完了のTODOのみ表示します。期限超過は、期限が現在時刻より前の未完了TODOです。完了済みと期限なしのTODOは含みません。

## 復元と一括削除

「データの保存・復元」でJSONファイルを読み込み、復元方法を選びます。ファイル選択だけでは保存データを変更しません。追加・更新・削除・復元後の件数を表示し、確認してから保存します。判定にはタイトルではなくTODOのIDを使用します。

| 復元方法         | 同じIDのTODO                                           | 新しいID | 現在だけのTODO |
| ---------------- | ------------------------------------------------------ | -------- | -------------- |
| 完全上書き       | メモも含めファイルの内容に置換                         | 追加     | 削除           |
| 更新＋新規追加   | タイトル・説明・期限・優先度・状態を更新し、メモを統合 | 追加     | 維持           |
| ないTODOだけ追加 | 変更しない                                             | 追加     | 維持           |

更新＋新規追加では、既存TODOの作成日時を保持します。メモはIDで重複を除き、送信日時の昇順に統合します。同じメモIDの内容が異なる場合は読み込んだ側を採用します。同じバックアップを繰り返し読み込んでも、同じIDのTODOやメモは増えません。

ファイルは10MB以下、復元後は10,000件以下のTODOに対応します。ブラウザの保存容量を超える場合は元のデータを維持して保存エラーを表示します。保存データを読み込めない場合は、元データの書き出しと完全上書き・初期化を案内します。

一括削除は「完了済みのTODO」「すべてのTODO」から選択でき、付属メモも削除します。TODOとメモの対象件数を確認してから実行し、一括削除の取り消しはできません。必要なデータは事前に書き出してください。画面には、このアプリの保存量の概算も表示します。

確認中に別タブで保存内容が変わった場合は、古い内容で復元・一括削除せず、対象の再確認を求めます。

## Googleカレンダー

APIキーやアプリ内のGoogle認証は不要です。「Googleカレンダーに登録」で入力済みの予定作成画面を別タブに開きます。利用者がGoogleアカウントでログインし、保存します。タイトルは「【締切】TODOタイトル」、開始は締切時刻、終了は15分後です。進捗メモは送信せず、TODOの説明を予定の説明に含めます。

Androidでアプリの起動だけになりやすい `r/eventedit` への直接リンクを避け、`calendar/render?action=TEMPLATE` を入口にしています。アプリへ移動して予定作成画面にならない場合に備え、別ホストの「ブラウザー版で開く」リンクも用意しています。端末のアプリ関連付けやログイン状態による遷移は、実機での確認が必要です。

保存したかどうかの検出、重複登録の防止、期限変更後の同期は行いません。期限なしの場合は、代わりに期限の設定を案内します。

## Vercelへの公開

1. このプロジェクトをGitHubリポジトリへpushします。
2. VercelでそのリポジトリをImportします。
3. Framework PresetはVite、Build Commandは npm run build、Output Directoryは dist を指定します。
4. Deployします。環境変数・データベースは不要です。

Hobbyプランは非商用の個人利用向けで、無料枠の上限があります。サービスの最新条件は公開時に確認してください。

## GitHub Pagesへの公開

同梱の .github/workflows/pages.yml がビルド・公開します。

1. 公開リポジトリへpushします。
2. Settings → Pages → Build and deployment → SourceでGitHub Actionsを選びます。
3. mainブランチへのpush、またはActionsから手動でワークフローを実行します。

Viteのbaseを相対パスにしているため、リポジトリ配下でも動作します。ルーティングは単一ページ内で完結し、サーバーのリライト設定は不要です。

## 技術構成

React / TypeScript / Vite / Tailwind CSS / Lucide React / Vitest。

メモは送信のみで、編集・削除操作はありません。Enterは改行、Ctrl+Enter（Macは⌘+Enter）は送信です。Googleカレンダーの操作は詳細モーダル右下に配置しています。

- src/App.tsx: 一覧・状態管理・確認
- src/DataPanel.tsx: バックアップ・復元方法の選択・変更件数のプレビュー・一括削除
- src/ui.tsx: モーダル・カード・フォーム・メモ
- src/model.ts: 型・日時・並べ替え・検索・カレンダーURL・保存形式の検証
- src/storage.ts: localStorageの読み書き
- src/model.test.ts: 並べ替え・期限・検索・カレンダー・バックアップのテスト
- src/App.test.tsx: 作成・メモの永続化・入力保護・保存失敗などの操作テスト（jsdom）
- src/DataPanel.test.tsx / src/restore.test.ts: 復元・メモ統合・一括削除・データ保護のテスト
- src/messages.ts: 画面文言・日時書式・件数などの文章生成
- src/components/TodoNavigation.tsx: メニューと件数表示、到着先のDOM参照
- src/completion/useCompletionQueue.ts: 保存済みの完了変更の予約・取り消し・到着管理
- src/completion/CompletionCelebration.tsx / completion.css: 完了演出の表示・スタイル
- src/completion/useCompletionAnimation.ts: Reactの参照・演出開始・中断条件
- src/completion/completionSequence.ts / completionMotion.ts: 演出の順序・タイミングと動きの設定
- src/completion/AnimationSession.ts: 再生中のアニメーション・タイマー・イベントの一括解放
- src/completion/completionTarget.ts: 目的地の実測・遊泳中の追跡
- src/completion/CompletionSplash.tsx: 件数の位置に合わせた到着時の水しぶき
- src/completion/CompletionNotice.tsx / completionNotice.css: 残件数に応じた完了通知
- src/completion/swimGeometry.ts: 実測した座標からの遊泳経路の計算
- src/completion/SeaLion.tsx / seaLionShape.ts: 関節を分けたトドの描画・カードからの輪郭補間
- src/completion/followOutline.ts: 共通クロックによる輪郭の描画更新
- src/index.css: Tailwindと画面スタイル
