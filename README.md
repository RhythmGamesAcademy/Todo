# トドTODO

## 概要・公開URL

トドTODO（トドトゥードゥー）は、トドが獲物を食い荒らすように、気持ちよく、便利にTODOを消化できるウェブアプリケーションです。TODOごとにチャット風の進捗メモを残せることと、完了したカードがトドに変身して泳ぐ演出が特徴です。

**[>トドTODOを使う](https://tzug1729.github.io/todo/)** 

 **[15秒の紹介動画を見る](docs/todo_promo_15s.mp4)**

ブラウザーだけで利用でき、このアプリのアカウント登録は不要です。TODOとメモは、利用している端末・ブラウザーのlocalStorageに保存します。

## 開発の背景と目的

TODOを管理するだけでは、「どこまで進めたか」「次に何をするか」が分かりにくく、完了させたときにも、もう少し達成感がほしいと感じていました。

そこで、タスクごとに進捗や気づきを時系列で残せる機能と、完了を楽しめる演出を組み合わせました。、機能の多さだけでなく、PCでもスマートフォンでも迷わず操作できることを目指しました。

## 主な機能と使い方

| 機能                     | できること                                                                                     |
| ------------------------ | ---------------------------------------------------------------------------------------------- |
| TODOの作成・編集・削除   | タイトル、説明、期限日時、優先度を設定できます。期限なしのTODOも作成できます。                 |
| 状態の管理               | 「未着手」「進行中」「完了」を切り替えられます。                                               |
| チャット風メモ           | TODOごとに、名前「自分」と送信日時付きのメモを時系列で残せます。                               |
| 一覧の切り替え           | カード表示とリスト表示、期限順と優先度順を選べます。表示形式は次回も引き継ぎます。             |
| 検索・絞り込み           | タイトル・説明・メモの検索と、未完了・期限超過・今日が期限・進行中・完了の絞り込みができます。 |
| 完了演出                 | カードがトドに変身して完了タブへ泳ぎ、件数とメッセージで達成を知らせます。                     |
| Googleカレンダーへの登録 | TODOの期限を使って、予定の作成画面を開けます。                                                 |
| データの保存・復元       | JSON形式のバックアップと、3種類の方法による復元ができます。                                    |
| 一括削除                 | 完了済みだけ、またはすべてのTODOと関連するメモを削除できます。                                 |

### 基本的な操作

1. **TODOを作る**から、タイトル・説明・期限・優先度を入力します。タイトルは必須です。期限が不要な場合は「期限を設定しない」を選びます。
2. 一覧のカードやリストの行を押して、詳細モーダルを開きます。ここで状態の変更、TODOの編集・削除、メモの送信ができます。
3. メモ欄には、「資料の整理まで完了」「次は図表を見直す」などを入力します。送信ボタンのほか、**Ctrl＋Enter／⌘＋Enter**でも送信できます。メモは追記式で、送信後の編集・個別削除はありません。
4. 状態を**完了**にして詳細を閉じると、未完了の一覧に切り替わり、完了演出が始まります。「演出をスキップする」またはEscキーで終了することもできます。

タイトルは120文字、説明とメモはそれぞれ2,000文字まで入力できます。入力欄には現在の文字数と上限を表示し、必須項目は赤い「必須」表示で区別しています。

「すべてのTODO」には完了済みも表示しますが、完了済みは末尾にまとめます。未完了・完了それぞれの中では、選択中の並び順を適用します。期限順では期限なしのTODOを最後に置き、これからの期限が最も近い未完了TODOには赤いアクセントを付けています。

### Googleカレンダーへの登録

期限を設定したTODOの詳細モーダル右下にある、**Googleカレンダーに登録する**を押します。タイトル・説明・期限を引き継いだ予定の作成画面が開くので、内容を確認し、Googleカレンダー側で保存してください。予定の開始はTODOの期限、終了はその15分後です。

Googleアカウントへのログインが必要な場合があります。スマートフォンで登録画面が正しく開かない場合は、併設した「ブラウザー版で開く」を試してください。この機能は予定作成用のリンクを開くもので、TODOと予定を自動で同期する機能ではありません。

### バックアップ・端末間の引き継ぎ

PCでは左下、スマートフォンではヘッダー右側の**データの保存・復元**から操作します。

1. 「書き出す」で、TODOとメモを含むJSONファイルを保存します。
2. 移行先の端末で同じアプリを開き、復元方法を選んでから「ファイルを選ぶ」を押します。
3. 追加・更新・削除される件数を確認し、「復元する」を押して確認ダイアログから実行します。

| 復元方法       | 既存データの扱い                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 完全上書き     | 現在のTODO・メモを、ファイルの内容に置き換えます。                                                                         |
| 更新＋新規追加 | 同じIDのTODOの内容を更新し、新しいIDのTODOも追加します。メモは両方を時系列で統合し、同じメモIDは読み込んだ側を採用します。 |
| 新規追加       | まだ存在しないIDのTODOだけを追加します。既存のTODO・メモは変更しません。                                                   |

データは端末・ブラウザーごとに保存され、クラウドでの自動同期は行いません。ブラウザーのサイトデータを消す前や、端末を変える前に、JSONのバックアップを取ってください。

一括削除では、実行前に対象のTODO・メモの件数を確認できます。**一括削除は取り消せません。** 削除後にTODOが0件になる場合は、TODO・メモの保存キーもlocalStorageから削除します。表示形式の設定は残します。

## 工夫した点

### チャット風の進捗メモ

説明文を書き直すだけでは途中経過が消えてしまうため、メモを追記して記録する形にしました。モダンなチャットアプリをイメージし、送信後は「…」に続いて本文が滑らかに現れます。メモ履歴と入力欄を同じ凹んだ領域にまとめ、どこをスクロールしているかも分かりやすくしました。

演出の完了を待たずにデータを保存し、途中でモーダルを閉じても送信済みのメモが残るようにしています。スマートフォンでは、送信ボタンを押した後に入力欄へフォーカスを戻さず、キーボードが意図せず開く問題を避けました。

### カード表示とリスト表示の切り替え

カード表示では最新のメモも見られるようにし、リスト表示では状態・タイトル・説明・期限・優先度に情報を絞りました。TODOが増えたときにも一覧を見渡しやすくしつつ、どちらの表示からも同じ詳細画面を開けます。「すべてのTODO」のアイコンも、選択中の表示形式に合わせて切り替えています。

検索・並べ替えの状態を保ったまま表示形式を切り替えられます。また、完了済みは白いカードや操作時の反応を残し、文字色だけを少し控えめにして、操作できない項目に見えないようにしました。

### トドに変身する完了演出

TODOが完了すると、そのカードをいったん大きく見せてから、輪郭をトドの形に変化させます。ヒレの動き、奥行きのある左右の旋回、加速を組み合わせて、完了したときの達成感を表現しました。

移動先は固定の座標ではなく、実際に表示されている完了タブの位置を測って決めています。PCでは左、スマートフォンでは上にあるタブへ向かい、到着時には完了件数が一瞬大きくなります。残りの未完了TODOに応じて、通知も緑・オレンジ・青に切り替えます。

演出と保存処理を分け、スキップや途中終了があっても完了状態が失われないようにしています。

### データの保存・バックアップ・復元

端末間で簡単に引き継げるように、JSON形式でTODOとメモを書き出せるようにしました。復元時には3つの方法を選べるため、データの移行だけでなく、既存のTODOを残した追加にも対応できます。

読み込むJSONの形式やIDの重複、日時などを検証し、保存に失敗した場合は画面上のデータや入力中のメモを消さないようにしました。壊れた保存データも自動で上書きせず、書き出しや復元を案内します。

### 見た目と操作の分かりやすさ

青と白、角丸、波のライン、透過した固定ヘッダーで、海とトドの印象を揃えました。時計は右上に配置し、数字の幅が変わりにくい設定を使っています。スマートフォンでは日付と時刻を2行に分けます。

余計なキャッチコピーは省き、状態や優先度を文字・アイコン・色で示しました。必須表示、文字数カウンター、一括削除前の確認など、見た目だけでなく、入力や誤操作への配慮も重視しています。一方で、「期限を設定しない」を自分で選んだ後の再確認は不要と判断し、ダイアログを外しました。

## 使用技術・設計

| 用途               | 使用技術                                       |
| ------------------ | ---------------------------------------------- |
| UI・状態管理       | React 19、TypeScript                           |
| スタイル           | Tailwind CSS 4、CSS、レスポンシブレイアウト    |
| アイコン・完了演出 | Lucide React、SVG、CSS、Web Animations API     |
| データ保存         | localStorage、JSON形式のバックアップ           |
| 開発・ビルド       | Vite、Node.js、npm                             |
| テスト・整形       | Vitest、React Testing Library、jsdom、Prettier |
| 公開・自動チェック | GitHub Pages、GitHub Actions                   |

バックエンドやデータベースを持たない構成です。Googleカレンダーへの登録も予定作成用のURLを生成する方式のため、このアプリ用のAPIキーや環境変数は不要です。

処理が1つのファイルに集中しないよう、保存、データ操作、表示、完了演出などの責務を分けています。

```text
src/
├── App.tsx          # 画面の状態と各機能の連携
├── ui.tsx           # TODOのカード・フォーム・詳細モーダルなど
├── components/     # ナビゲーション・状態バッジなど
├── model.ts         # 型、検索・並べ替え、JSON検証、復元処理
├── storage.ts       # localStorageへの保存と読み込み
├── DataPanel.tsx    # バックアップ・復元・一括削除
├── messages.ts      # 表示文言・日時の書式
└── completion/      # トドの形状・移動経路・演出の進行管理
docs/                # スクリーンショット・GIF・紹介動画
public/              # トドのロゴなどの静的ファイル
```

表示文言は `src/messages.ts` にまとめ、文章の調整や今後の多言語対応を進めやすくしています。テストファイルは対象の実装の近くに配置しています。

## 起動方法

Node.js 24とnpmを使用します。

```bash
git clone https://github.com/tzug1729/todo.git
cd todo
npm ci
npm run dev
```

ターミナルに表示されるURLをブラウザーで開いてください。

| コマンド          | 内容                                         |
| ----------------- | -------------------------------------------- |
| `npm run dev`     | 開発用サーバーを起動                         |
| `npm test`        | 自動テストを実行                             |
| `npm run build`   | TypeScriptの型チェックと本番用ファイルの生成 |
| `npm run preview` | ビルド済みのアプリをローカルで確認           |
| `npm run format`  | Prettierでコードや文書を整形                 |

公開にはGitHub Pagesを使用しています。`main` ブランチへのpush時にGitHub Actionsで依存関係のインストール・テスト・ビルドを行い、成功した場合にデプロイします。

## 動作確認・テスト

VitestとReact Testing Libraryを使用し、現在**73件の自動テスト**を用意しています。

- TODOの作成・編集・削除、状態の変更、検索・並べ替え、表示形式の保持。
- メモの連続送信、保存、表示演出、保存失敗時の入力保持。
- 3種類の復元方法、メモの時系列統合、不正なJSONの拒否。
- 一括削除の対象・件数・確認・キャンセルと、0件になったときの保存キーの削除。
- 完了演出の行き先の追跡、スキップ、完了の取り消し、保存失敗時の扱い。
- 時計の毎秒更新と日付をまたぐ場合の表示。

ChromeでPC向けの表示と、幅320px・390px・600pxの表示を確認しました。スマートフォン幅の確認はブラウザーの表示領域を変更して実施し、ヘッダーの重なり、2列カード、リスト表示、長い文章の折り返しなどを確認しています。

## 今後の改善

今後は、組織でも使えるタスク管理アプリに発展させたいと考えています。担当者を設定し、今の進捗メモを複数人のチャットに広げることで、タスクで詰まったときに上司やメンバーへメンションして相談できるようにしたいです。

現状は1人用・ブラウザー内保存のアプリなので、共同利用に向けて、サーバーとデータベース、認証、閲覧・編集権限などを学ぶ必要があります。そのほか、多言語対応や、スマートフォン実機での検証環境を増やすことにも取り組みたいです。

## 振り返り・学んだこと

### 小さな操作の違いが使いやすさに繋がること

PCで動いていても、スマートフォンではリストが大きすぎたり、メモ送信後にキーボードが開いたりしました。見た目を縮めるだけでなく、余白、フォーカス、スクロール、ボタンの位置まで確認する必要があると学びました。確認ダイアログも、多ければよいのではなく、必要な操作に絞ることが大切だと感じました。

### アニメーションとデータの状態を分けて考えること

完了演出では、画面サイズによって移動先が変わり、途中で閉じたりスキップしたりする場合もあります。データを先に保存し、実際の画面位置を測って演出することで、見せ方とデータの整合性を分けて扱えることを学びました。

### 文言の変更もテストに影響すること

`messages.ts` のボタン名を変更したところ、古い文言を直接指定していたテストが失敗しました。表示文言を一元化するだけでなく、テスト側でも共有する必要があると分かりました。

また、テストが通っても、テストコードの型エラーで本番ビルドが失敗したことがありました。動作のテストとTypeScriptの型チェックは役割が違うため、**`npm test` と `npm run build` の両方を確認する**ことが大切だと学びました。

### 保存や復元には、正常な場合以外の設計も必要

localStorageへの保存失敗、不正なJSON、重複するIDなども考える必要がありました。「保存できなかったのに入力を消さない」「確認前に元のデータを変更しない」など、失敗したときに利用者のデータを守る設計の大切さを学びました。
